## 1. Trae CN 3.4.7 架构（已确认）

### 1.1 进程与二进制

| 角色 | 进程特征 | 二进制 |
|---|---|---|
| 主进程 / 渲染进程 | Electron (VSCode 1.107.1) | `Trae CN.exe` |
| AI sidecar（聊天核心） | `--utility-sub-type=basil.mojom.NativeExtensionService --vscode-crash-reporter-process-type=ai` | `ai_agent.dll`（267.24 MB） |
| ai-server（3.4.7 新增） | `--vscode-crash-reporter-process-type=ai-server`（`node.mojom.NodeService`） | `harness.dll`（209.70 MB） |
| toolhost（工具执行） | 命名管道 `\\.\pipe\agent-code-toolhost-<pid>-<hash>` | `toolhost.dll`（87.30 MB） |
| 网络库 | TTNet / cronet | `sscronet.dll`（8.70 MB） |

`modules\ai-agent\meta.json` 里声明 `{"connections":[{"socket":{"port":40005}}]}`，但 **sidecar 实际不在 40005 上监听**（已验证）。

### 1.2 聊天 RPC 走 mojo，不走 TCP/管道

- sidecar 与 ai-server 都带 `--mojo-platform-channel-handle=NNNN`。
- 没有任何可连接的 TCP 端口、没有可 `CreateFile` 的命名管道承载聊天流量（toolhost 管道只做工具执行）。
- **结论：聊天请求体无法从进程外动态捕获**（见第 4 节失败清单）。

### 1.3 sidecar 内部

- 34 个 Handler：`ChatHandler` / `ModelHandler` / `LiteHandler` / `ToolcallHandler` …
- JS → sidecar 13 个 RPC service：`agent`, `browser`, `commercial`, `configuration`, `context`, `context_asset`, `git`, `ide`, `lite`, `plugin`, `skill_import`, `system_diagnosis` …
- 配置缓存（关键）：`model_config_cache` 表

```sql
INSERT INTO model_config_cache (user_id, env, function, config_data, updated_at)
VALUES (?,?,?,?,strftime('%s','now'))
ON CONFLICT(user_id, env, function) DO UPDATE SET
  config_data=excluded.config_data, updated_at=excluded.updated_at
```

日志串：
- `Retrieved model config cache for user: ~~, env: ~~, function: ~~, configs count:`
- `No cached config found for user: ~~, env: ~~, function: ~~`
- `batch: function ~~ failed with error_code=~~`

→ **配置记录是按 `function` 查的，`2001 record not found` 就是 `function` 键不对。**

### 2.9 错误码

| code | 含义 | 触发条件 |
|---|---|---|
| `4001` | `We're sorry, the param is invalid.` | **头混用**（现代头 + legacy 设备头）或缺必填参数 |
| `2001` | `failed to do chat: failed to get app config: record not found` | **已过鉴权**，但 `function` 键查不到配置记录 |
| `4023` | model unknown | V1 chat 传了未知模型名 |
| `404` | 路径错 | 例如 `/api/ide/v1/commercial/get_mode_info`（正确是 `/api/v1/commercial/get_mode_info`） |
| `500` | 服务端炸 | `get_detail_param` 传 `model_names` |

### 2.11 ⚠️ 重要陷阱：providers 不是第一方额度池

`providers` 返回的模型（`deepseek-v4-flash`、`doubao-seed-2-1-*-260628`、`glm-5.3`、`kimi-k3`、`minimax-m3`、`qwen3.8-max`、`doubao-seed-evolving` …）是 **BYO-key `billing_mode:"paygo"` 池**，不是 Trae 第一方额度。
**不要拿这些名字去解锁 V1 chat**（必然 `4023`）。

## 3. 当前代码状态

### 3.1 `trae2api/gateway.py`（已改，未提交）

## 4. 已经试过并且**确认失败**的路（别再走）

| 方案 | 结果 | 证据 |
|---|---|---|
| mitmproxy 系统代理抓 sidecar | ❌ sidecar 完全不走系统代理 | 76 条请求中 `trae-api-cn.mchost.guru` **一次都没出现**；只有 `api.trae.cn`(82)、`api.trae.com.cn`(66)、`bytegate-sg`(4)。产物：`logs/mitm-requests.jsonl`（152 条 / 1085 KB）、`D:\trae_capture.flow`（7860 KB） |
| `ICUBE_PROXY_HOST=127.0.0.1` / `ICUBE_PROXY_PORT=8081` + `--preserve-env` | ❌ 无效（用户已确认） | sidecar 用 TTNet/cronet，绕过系统代理 |
| 连 `40005` 端口 | ❌ 没监听 | `meta.json` 是历史遗留声明 |
| 连 mojo 命名管道 | ❌ 单实例、不可附加 | `io.open(pipe,"r+b")` 无 `read1`；`os.open` EINVAL |
| `ReadProcessMemory` 读 sidecar 内存 | ❌ 拿不到完整请求体 | `memscan_sidecar.py` |
| `netsh trace` | ❌ 需提权且 TLS 载荷加密 | — |
| 解 `.alaudalog` | ❌ 加密 | magic `AalG` / `Atab`，zlib 全变体失败 |
| 用 `providers` 模型名解锁 V1 | ❌ 必然 `4023` | providers 是 BYO-key paygo 池（2.11） |
| 现代头 + legacy 设备头混用 | ❌ `4001` | 必须**纯** `_modern_headers()` |

**核心结论：sidecar 用 TTNet/cronet 直连，进程外无法拿到 LLM 请求体；只剩静态逆向 + 黑盒探测两条路。**
