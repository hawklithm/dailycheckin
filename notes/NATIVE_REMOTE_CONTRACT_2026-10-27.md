## Offline body projection helper

`tools/native_body_projection_core.js` is a pure in-memory helper for a possible later observer. It installs no hook and has no Frida, process, file, or network calls. A caller would need to establish typed request/provider/callback/buffer provenance and an exact HTTPS host/port/method/path-hash match before passing any already-read bytes to it.

The helper keeps the accepted marker and target model fixed, checks upload bytes against the captured buffer-size snapshot and byte count, bounds upload/response/combined data to 1 MiB / 2 MiB / 4 MiB, caps active flows, pending reads, and pointer-identity history, and emits only allowlisted schema/type, model/config, ID hashes, usage, event, done/error, and role metadata. Ambiguous mapping, sequence, rewind, or terminal cases fail closed. The helper is not integrated into `tools/native_metadata_observer.js` and does not show that the current Cronet call path reaches the reviewed wrappers.

The helper now requires an explicit request-marker contract before it accepts an upload read; without one, `beginUploadRead` fails closed and no response gate can open. The local fixture contract selects the last entry in a synthetic `messages` array and requires `role=user` plus a matching `content` field. This only tests the selector mechanism; it does **not** claim that the native wire body has a `messages` field or this shape. Before any live use, the actual outbound schema must be established and the selector must be mapped to the current synthetic user-input field, excluding old history and unrelated metadata. Exact route and typed request/provider/buffer provenance permit only a bounded upload read needed to evaluate that user-field gate; only a semantic match on that same request permits response projection.

A response marker in an `assistant` content field can still be a prompt echo; it is a field match, not proof of model generation. The current SSE projection processes each parsed event frame independently, so a marker split across multiple content-delta frames can be missed. Before any live body capture or success claim, the wire schema and same-request association must be reviewed, and the fixed assistant-output marker must be confirmed in the UI.
